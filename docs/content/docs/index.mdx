**Lego-RL** is a framework for training coding agents with online
reinforcement learning on real software-engineering tasks. It connects
unmodified agent harnesses — Claude Code, OpenHands, OpenCode, Terminus — to
[verl](https://github.com/volcano-engine/verl)-based policy optimization:
every trial runs in a fresh [Harbor](https://github.com/SWE-Lego/harbor)
sandbox, the task's own test suite produces the reward, and training data is
captured at token level directly from the serving path.

## Key features

- **Unmodified agents** — the agent that produces a rollout is the deployed agent.
  Each scaffold is a thin adapter, not a fork. Claude Code, OpenHands, OpenCode, and
  Terminus are validated end to end; any scaffold speaking the OpenAI or Anthropic API
  can be added as a
  [custom adapter](/docs/architecture/agent-loop-workers#agent-loop-classes).
- **Token-level trajectory capture** — an
  [in-process proxy](/docs/architecture/in-process-proxy) serves one unified
  OpenAI/Anthropic API and records token ids, masks, and log-probabilities at
  generation time. No transcript re-tokenization, and history rewriting by the agent
  does not corrupt the signal.
- **MoE routing replay (R3)** — rollout-time expert routing is recorded and replayed
  during the update, keeping rollout and training log-probabilities aligned
  (`pearson ≈ 0.999`) for sparse policies.
- **Verified rewards in real sandboxes** — each task's verifier runs its test suite in
  a fresh [Kubernetes or Docker](/docs/run-training/backends) container, with image
  caching, lazy pull, and anti-hacking defenses. Broken environments are
  [filtered out of the loss](/docs/architecture/rollouter) rather than polluting the
  gradient.
- **Scalable training** — PPO / GRPO / GSPO over full multi-turn rollouts on
  [FSDP, VeOmni, or Megatron](/docs/architecture/trainer#backends), from a synchronous
  single-node loop to a fully-asynchronous multi-node cluster with
  [partial rollout](/docs/architecture/trainer). See
  [Scaling Up](/docs/run-training/scaling).
- **Operations included** — [preflight](/docs/run-training/preflight) config
  validation, an [agent plugin](/docs/agent-plugin) for guided launches, a
  self-contained [dashboard](/docs/dashboard), and symptom-indexed
  [troubleshooting](/docs/troubleshooting).

## Training Infrastructure

Each layer has its own page in [Block Design](/docs/architecture):

1. **[Environment](/docs/architecture/environment)**: each task runs in a fresh
   sandbox (a Kubernetes pod or a local/remote Docker container — setup and
   permissions in [Backends](/docs/run-training/backends)) with sandboxed
   execution plus the task's own **verifier**. A coding-agent scaffold — Claude
   Code, OpenCode, OpenHands, Terminus 2 — drives the model through the task.
2. **[AgentLoopWorkers](/docs/architecture/agent-loop-workers)**: run the scaffolds
   concurrently and capture each rollout.
3. **[In-Process Proxy](/docs/architecture/in-process-proxy)**: fronts every worker
   with a single, unified OpenAI/Anthropic API — it captures the trajectory
   (token-in / token-out) and forwards each call onward. No standalone LiteLLM.
4. **[Global Load Balancer](/docs/architecture/global-load-balancer)**: spreads
   requests across inference replicas with sticky, per-session routing.
5. **[Rollouter](/docs/architecture/rollouter)**: a pool of vLLM inference servers
   serves the policy, streams completed rollouts into a **Data Buffer**, and
   receives **Weight Sync** updates.
6. **[Trainer](/docs/architecture/trainer)**: verl consumes the buffer, computes
   advantages, and updates the actor (PPO / GRPO / GSPO), then syncs new weights
   back to the rollouter for the next round.
