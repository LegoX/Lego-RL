The **In-Process Proxy** (`src/verl_patch/agent_loop/vllm_chat_completion_proxy.py`)
is the single seam between every scaffold and the self-served policy: one
process, one unified API, exact token-level capture — **no standalone LiteLLM,
no fixed port**.

## Unified API

The proxy is started by the verl agent loop on the training host, binds an
ephemeral port, and hands each trial a unique **per-session URL**. Both protocol
families are served from the same process:

```python
# vllm_chat_completion_proxy.py — route table
self._app.router.add_post("/sess/{session_id}/v1/chat/completions", self._handle_chat)      # OpenAI
self._app.router.add_post("/sess/{session_id}/v1/messages",         self._handle_messages)  # Anthropic
self._app.router.add_get ("/v1/models",                             self._handle_models)
```

A scaffold needs zero changes — its base URL is overridden per trial:

```bash
# Claude Code                          # OpenHands / OpenCode / Terminus
ANTHROPIC_BASE_URL=http://<host>:<port>/sess/<id>   OPENAI_API_BASE=http://<host>:<port>/sess/<id>/v1
```

## Trajectory capture

The proxy records the exact engine prompt, sampled tokens, behavior logprobs
and routing metadata in context-preserving segments. Only sampled tokens have
`response_mask=1`; tool observations, template tails and historical assistant
messages in a new prompt have mask zero.

An append extends the current segment. A rewritten engine prompt starts another
segment after generation succeeds, retaining earlier actions under their original
contexts. For example:

```text
segment 0: Q A1 O1 A2 O2 A3    train A1, A2, A3
segment 1: Q A1 Z A3 O3 A4     train A4 only
```

The previous prefix-logprob recomputation path is removed: scoring A3 under a
rewritten prefix cannot recover its original sampling context. Exact retries or
replacement of the latest assistant roll back that generation only when the
replacement succeeds. Discarded generations are retained for inspection.

At trial end, `proxy_trajectory.json` stores all `trajectory_segments`, discarded
retries, and the latest messages/tools. Training selection is described under
[AgentLoopWorkers](/docs/architecture/agent-loop-workers#context-segment-selection).
Existing subagent isolation still applies: changes to the initial conversation
identity route to an untrained sub-session. Multimodal trajectory capture and
arbitrary branch identity remain outside this path's scope.

## Admission control

Before a call is forwarded, it passes an optional admission gate — the
[Session-Level Scheduler](/docs/architecture/session-scheduler). Disabled by
default; when enabled it holds cold sessions back under high KV pressure so
resident prefixes are not evicted.

## Partial rollout

Because the proxy forwards to verl's `server_manager` rather than to vLLM
directly, vLLM aborts/retries — and the fully-async **partial rollout** path
(resuming a generation interrupted by a weight sync) — are handled transparently
on the way through.
